全体の関係図

各設定の依存関係が1枚でわかる図： 選んだバックエンドによって、下の画質の設定のどれが実際に効くかが決まる。

図から覚えておきたい2つのこと： API の数字が大きいほど画質が高いわけではない。まず決まるのは、命令がどのランタイム・ラッパー・グラフィックドライバーを通るかです。Ephinea の高度なアンチエイリアスは D3D9 以上で使えます。D3D11／12 はさらに dgVoodoo を、Vulkan は DXVK を使います。 dgVoodoo Model だけは D3D11／12 の経路に限られます。

描画のバックエンド（D3D／Vulkan）

PSOBB のエンジンが出すのは本来 Direct3D 8 の命令だけです。ランチャーの設定はモデル・テクスチャ・場面の光を書き換えるのではなく、その命令がその後どの互換レイヤー・出力の API・グラフィックドライバーを通るかを決めます。厳密には、このドロップダウンはネイティブの API・変換の経路・ラッパーの出力のバックエンドを混ぜたもので、同じ種類の「レンダラー」がいくつか並んでいるわけではありません。

まず描画の流れを正しく理解する

現代のバックエンドは PSOBB をネイティブの D3D11 や D3D12 のゲームに変えるわけではありません。ゲームは今も D3D8 時代と同じ頂点・テクスチャ・固定機能の状態・描画の命令を出し、互換レイヤーがそれを新しい API が理解できるリソース・状態・シェーダーに書き換えてから、グラフィックドライバーに渡します。

PSOBB の内容と処理

Ephinea の互換・強化レイヤー（D3D9 の経路、AA、AF、後処理）
    ├─ D3D9 ───────────────────────────────→ D3D9 のドライバー
    ├─ D3D9 → Microsoft D3D9On12 ─────────→ D3D12 のドライバー

ランチャーのカスタムファイルが dgVoodoo_d3d9.dll か dxvk_d3d9.dll である理由もこれで分かります。ラッパーは Ephinea が出す D3D9 の呼び出しを受け取り、D3D11・D3D12・Vulkan へ渡します。Ephinea の公式の Launcher 3.5.0 の更新情報にも、この2つのファイル名とバージョンの関係が書かれています。

D3D8／D3D9／9on12／11／12／Vulkan の比較

まず区別すべき3つのこと：D3D8／9／11／12 と Vulkan はグラフィック API、D3D9On12 は Microsoft のマッピングレイヤー、dgVoodoo と DXVK はサードパーティの変換ツールです。Ephinea のドロップダウンは、これらの違う層を選びやすい「バックエンド」としてまとめたものです。

D3D8 から D3D9 は旧式の API の段階的な改良で、固定機能と従来のデバイスのリセットの仕組みを保っています。D3D11 は現代の GPU の機能をドライバーが管理する高水準の仕組みで包み、D3D12 と Vulkan はリソースの状態・命令の送信・同期を明示的に上の層に任せます。D3D9On12 が変えるのは D3D9 の下の実装だけで、PSOBB や Ephinea の前段がネイティブの D3D12 になるわけではありません。

画質：たいてい同じなのに、1ピクセル単位では保証されない理由

API そのものが「D3D12 級の画質」を与えるわけではありません。キャラクターのポリゴン数、テクスチャの解像度、材質、光の計算式、影、エフェクトは今も PSOBB が決めます。出力の解像度・AA・AF・SSAO・シェーダーがまったく同じなら、D3D9・D3D11・D3D12・Vulkan の画面はとても近くなるはずです。

ただし、各経路はビット単位で同じ再生ではありません。ラッパーは D3D8／9 の固定機能パイプラインを再現し、旧式の形式と状態を現代のシェーダーとリソースに変換する必要があり、次のような細部で見た目の違いが出ることがあります：

  • サンプリングとフィルタリング：テクスチャ座標の精度、ミップマップの LOD、異方性フィルタリング、半ピクセルの規則で、テクスチャの鮮明さが少し変わることがあります。
  • 深度とブレンド：深度バッファの形式、比較の精度、Alpha Test／Blend の再現の違いで、つなぎ目・ちらつき・透明の順番の乱れが出ることがあります。
  • 固定機能の再現：頂点フォグ・光・反射・テクスチャのステージはシェーダーに変換する必要があり、ラッパーの不具合でフォグが消える、反射がおかしい、色がずれるといったことが起きます。
  • 色と表示：ガンマ、色空間、拡大縮小のフィルター、スワップチェーンの合成方法が、明るさ・コントラスト・最終的な鮮明さに影響します。

そのため、バックエンドによって明らかな黒い塊、おかしなフォグ、反射の欠け、全体の暗さが出たときは、ある API の正常な「絵柄」ではなく、互換性の違いか変換の誤りとして扱ってください。バックエンドを切り替える主な意味は、今の GPU・ドライバー・ウィンドウのモードで最も正しく安定した実装を見つけることです。

D3D9on12 と D3D12 はなぜ別物なのか？

どちらも最終的に D3D12 のドライバーを呼びますが、変換するもの、上に見せるデバイスの仕組み、表示の管理がすべて違います。「最後に D3D12 を使う」だけでは動作を判断できません。

D3D11 と D3D12 は実際どこが違う？

結論：どちらも dgVoodoo の D3D9 の前段・状態の変換・固定機能の再現を共有し、最後のリソース管理・命令の送信・同期・表示の層だけが分かれています。そのため機能と期待できる画質は同じで、D3D12 は画質を上げた D3D11 ではありません。

D3D12 と Vulkan の下での関係

D3D12 と Vulkan は同じ世代の低水準のグラフィック API で、設計の考え方はとても近いです。どちらも、以前は D3D11 のドライバーが暗黙に行っていた多くの仕事をアプリや変換レイヤーに任せます。GPU の命令を先に記録する、リソースの状態を明示する、パイプラインのオブジェクトをまとめる、ディスクリプターをバインドする、CPU と GPU の同期を扱う、といった仕事です。このページで扱う PSOBB の場合、それを担うのはゲーム本体ではなく dgVoodoo や DXVK です。

主な違いは「高水準か低水準か」ではなく、エコシステムとインターフェースの決まりにあります。D3D12 は Microsoft の Windows／Xbox のグラフィックの系統に属し、DXGI・HLSL／DXIL・Windows のドライバーモデルを使います。Vulkan は Khronos が定め、Windows・Linux・Android で動き、普通は SPIR-V を使い、独自の表示と拡張の仕組みを持っています。Vulkan のほうが明示的な選択肢を多く見せる傾向がありますが、どちらも上の層がリソースの寿命・同期・パイプラインを正しく管理する必要があります。

PSOBB → D3D8 → Ephinea D3D9 → dgVoodoo → D3D12 → Windows のグラフィックドライバー → GPU
PSOBB → D3D8 → Ephinea D3D9 → DXVK     → Vulkan → Vulkan のグラフィックドライバー  → GPU

そのため dgVoodoo + D3D12 と DXVK + Vulkan は同じ種類の現代の低水準の変換の経路と考えられますが、同等ではありません。2つの変換ツールは、D3D9 の固定機能・シェーダー・古いテクスチャの形式・深度バッファー・スワップチェーン・デバイスロストの再現のしかたが違います。こうした実装の違いのほうが、API の名前よりも PSOBB の正しさ・カクつき・安定性を大きく左右します。30 FPS の古いゲームでは、低水準の API の理論上の処理能力の利点はたいてい重要ではなく、正しく安定して描画できる経路を優先してください。

Ephinea が提供する変換レイヤーのバージョン

括弧内の数字は「D3D の小さなバージョン」ではなく、変換ツールのリリースのバージョンです。複数のバージョンを選べるようになったのは Ephinea Launcher 3.5.0 とクライアントの DLL 1.860 の組み合わせからで、同じリリースの投稿でその後 DLL 1.861 がスタックの破壊を、1.862 が誤って起きる強制終了を修正しました。つまり 1.860 は機能が入ったバージョンであり、固定して使うべきバージョンではありません。クライアントは常にゲーム内のパッチを最後まで当ててください。ランチャー／DLL はファイルを選んで読み込むもので、それ自体はグラフィック API ではありません。

Device Lost のエラー：どのバックエンドで出て、どれで避けられるか？

このエラーはクライアントがデバイスロストを受けた後、復旧（Reset）に失敗したことを表します。「dgVoodoo 2.79.3 専用のエラー」や「D3D12 専用のエラー」ではありません。調べるときは、まず2種類の原因を区別します：

  • 従来の D3D8／9 のデバイスロスト：排他的なフルスクリーンがフォーカスを失う、Alt-Tab、UAC の安全なデスクトップ、ロック画面、スクリーンセーバー、画面のモードの切り替えで起きます。PSOBB でこのエラーが出る最も多い原因です。
  • 本当の GPU／ドライバーのリセット：Windows の TDR、ドライバーの異常終了、不安定なオーバークロック、オーバーレイや注入の競合、変換ツールの不具合。D3D12 では Device Removed／Hung、Vulkan では VK_ERROR_DEVICE_LOST として現れることがあり、どのバックエンドでも必ず防げるとは限りません。

各バックエンドの意味

Direct3D 8

ゲームの本来の描画です。変換レイヤーを通さず、システムの D3D8 を直接呼びます。2003年の本来の動作に最も近いです。

  • ✅ 変わる要素が最も少なく、ゲーム本体が正常に動くかの確認に向く
  • ⚠ Win10／11 で高リフレッシュレートや複数のモニターを使うと、落ちる・ティアリング・Alt-Tab 後の黒い画面が起きやすい
  • ⚠ D3D9 以上の経路にある高度な AA の組み合わせがそろっていない。従来の Device Lost の動作も残る

Direct3D 9

軽いラッパーで D3D8 の呼び出しを D3D9 に変えます。負荷はごくわずかで、動作は本来に近く、純粋な D3D8 より少し安定しています。

  • ✅ 互換性が広く、D3D9 に対応するほぼすべてのグラフィックカードで動く
  • ✅ Ephinea の SSAA・SMAA・MSAA・HSAA などの高度な AA に対応
  • ⚠ 今もシステムの D3D9 のドライバーの品質に左右される
  • ⚠ 公式の更新記録によると、D3D9 の経路では MSAA／HSAA で一部の反射が壊れることがある。問題が出たら SMAA か SSAA に替える

Direct3D 9on12

Microsoft の公式の D3D9-on-D3D12 変換レイヤー。D3D8 の呼び出しをまず D3D9 に通し、次に Windows 内蔵の d3d9on12.dll が D3D12 に変換してグラフィックカードに送ります。

  • ✅ システムが D3D9 の処理を D3D12 に当てはめる。主にプラットフォームの互換の経路
  • ⚠ Ephinea の D3D9 の前段の動作をそのまま保ち、dgVoodoo の D3D12 モードではない
  • ⚠ Ephinea の公式のテストで、UAC・安全なデスクトップ・ロック画面の後に Device Lost が起きうるとされている。普通のパソコンでは優先して選ばないこと

Direct3D 11 (2.79.3 / 2.87.1)

dgVoodoo2 が Ephinea の D3D9 の呼び出しを受け取り、 D3D11 に出力します。旧式の固定機能の状態は、ラッパーが現代の GPU のリソースとシェーダーとして再現します。

  • ✅ ネイティブの D3D8／9 の Device Lost の問題を避けられる。ウィンドウモード・Alt-Tab・現代のデスクトップの合成がたいていより安定
  • ✅ Auto・Discard・Flip などの表示方式を選べる
  • 📌 まずはこれを試す：対応するハードウェアが広く、D3D12 と比べて問題を調べるときの妥当な出発点
  • 📌 2.79.3 は古い安定版、2.87.1 は新しい版で、機能は多いがときどき新しい不具合がある

Direct3D 12 (2.79.3 / 2.87.1)

上と同じですが、dgVoodoo2 がより新しい D3D12。

  • ✅ 一部の新しいグラフィックカードとドライバーの組み合わせで、CPU やドライバーの負荷が下がることがある
  • 📌 画質は D3D11 より高くならない。PSOBB ではたいていフレームレートの明らかな向上もない
  • 📌 常に Flip Discard で表示する。「dgVoodoo Model」のほかの選択肢でも従来の BitBlt 方式にはできない
  • ⚠ dgVoodoo の公式は現在、NVIDIA のドライバーでの D3D12 の GPU のハングをはっきり警告している。NVIDIA では第一候補にしないこと
  • ⚠ AMD で D3D11 に単色のポリゴンが出るなら D3D12 を試し、落ちるなら Radeon Anti-Lag をオフにして試し直す

Vulkan (2.3.1 / 2.7.1)

DXVK Ephinea の D3D9 の呼び出しを Vulkan に変換します。ドライバーのコンパイル・リソース管理・表示が別の経路になるので、問題が Direct3D のドライバーの系統だけで起きているかの確認に向いています。

  • ✅ 一部のハードウェアでは、D3D の経路特有のカクつきや表示の誤りが改善することがある
  • ⚠ Vulkan のシェーダーやパイプラインを初めて作るときに短いカクつきが出ることがある。程度はドライバーと DXVK のバージョンによる
  • ⚠ DXVK は Windows を公式にはサポートしていない。録画ソフト・オーバーレイ・RTSS などの注入するソフトと競合することもある
  • 📌 2.3.1 は古い安定版、2.7.1 は新しい版

自分で用意した の dgVoodoo か DXVK のバージョン。Ephinea の公式の決まりに従い、ゲームのフォルダーの dxdg フォルダーに x86 の dgVoodoo_d3d9.dll か x32 の dxvk_d3d9.dll。

  • 正しいバージョンのファイルを自分でダウンロードして置く必要があり、新しい変換レイヤーを試したい上級者向け
  • 間違ったファイルを置くと、起動時に黒い画面になったり落ちたりする

アンチエイリアス（Anti-Aliasing）

ジャギーは1種類の現象ではありません。PSOBB では少なくとも3種類が見られます：ポリゴンの輪郭の形状のジャギー、遠くの細かいテクスチャや柵がカメラの動きでちらつくテクスチャとアルファテストのジャギー、そして低い解像度で描画して拡大したときの全体的なサンプリング不足です。AA の方式ごとに対象が違うので、名前の後の 2x／4x だけで比べることはできません。

AA はどの層が実装している？

Ephinea の AA は、D3D11・D3D12・Vulkan が自動で付けてくれる画質の機能ではありません。クライアントがレンダーターゲットを作るときと最終の画像を処理するときに実装しています。MSAA はレンダーターゲットのマルチサンプリングの設定を変え、SSAA は内部の描画サイズを上げてから縮小し、SMAA は場面を描き終えた後に空間の後処理をします。Ephinea の開発者による実装の説明でも、この順番がはっきり示されています。

基本の方式

  • None — アンチエイリアスなし。性能は最もよく、輪郭は最も鋭いがギザギザ。
  • MSAA 2x / 4x — Multi-Sample AA。1つのピクセルの中の複数の位置で三角形の覆い具合と深度／ステンシルの結果を計算し、ピクセルのシェーディングは普通1回分を共有します。主に形状の輪郭をなめらかにし、SSAA より軽いですが、テクスチャの内側のちらつきやシェーダーのジャギーは直せず、アルファテストで作られた葉や柵の輪郭にもたいてい効きません。Microsoft の MSAA のラスタライズの規則でも、表面のジャギーは消えないとはっきり書かれています。
  • SSAA 2x / 4x — Super-Sample AA。Ephinea は幅と高さをそれぞれ 2倍か4倍にして描画し、線形のフィルターで出力の解像度に縮小します。形状の輪郭・テクスチャの細部・一部の透明な輪郭をまとめて改善でき、効果は最も広範囲ですが、ピクセルのシェーディング・ビデオメモリ・帯域の負荷が大きく増えます。
  • SMAA Low / Medium / High / Ultra — Subpixel Morphological AA。場面を描き終えた後、色や明るさの輪郭から形を探し、隣のピクセルと混ぜます。形状の輪郭と一部のアルファテストの輪郭に効き、負荷は比較的軽いですが、形状や時間の追加のサンプルがないので、ピクセルより細かい細部を本当に取り戻すことはできず、カメラの移動でのテクスチャのちらつきも確実には消せません。品質を上げるほど探す範囲と精度が上がり、副作用として細い文字・HUD・テクスチャが少しぼやけることがあります。
  • HSAA 2x / 4x — Hybrid-Sampling AA。Ephinea では同じ倍率の SSAA + 同じ倍率の MSAAのことで、2つの間の安い妥協案ではありません。内部の解像度とピクセルごとの覆いのサンプルを両方上げるので、画質の上限は高いですが、最も重い選択肢の1つでもあります。

SSAA／HSAA の倍率は実際どれくらい？

倍率は横と縦の両方にかかります。出力の大きさを W × H とすると、SSAA Nx の内部の大きさは (N·W) × (N·H) で、ピクセル数は N² 倍です。SSAA 4x を「4倍のピクセルを描くだけ」と誤解しないでください。

1080p の出力の例内部の解像度内部のピクセル数1080p との比
SSAA なし1920 × 1080約 207 万1×
SSAA 2x3840 × 2160約 829 万4倍のピクセル
SSAA 4x7680 × 4320約 3318 万16倍のピクセル

HSAA はこの高解像度のレンダーターゲットにさらに MSAA のサンプルを加えます。たとえば HSAA 4x は、おおよそ16倍のピクセルのシェーディングに4つの覆い／深度のサンプルを加えたものと考えられます。合計の時間がちょうど64倍になるわけではありませんが、レンダーターゲット・深度バッファー・帯域・ビデオメモリの負荷はとても高くなることがあります。PSOBB が古くても、4K 出力で 4x を使うと、起動に失敗したり、フレームが落ちたり、ラッパーに設定した VRAM を使い切ったりすることがあります。

20年前のハードウェアでなめらかだったのに、なぜ RTX 4090／5090 が 4K の最高設定で苦しむことがあるのか？

この2つは矛盾しません。本来の PSOBB は形状の複雑さ・シェーダーの複雑さ・30 FPS の上限がどれも低く、20年前のグラフィックカードでも 640×480、800×600、1024×768 で現代の後処理なしなら設計どおりに動きました。現代のランチャーでは、1フレームごとに処理するピクセル・サンプル・全画面のパスを何桁も増やせます。ゲームの中身は古いままでも、GPU が実際に行う仕事はもう 2004年の負荷ではありません。

4K の最高設定でのビデオメモリとサンプル数の見積もり

4K の出力は 3840×2160 で約 829 万ピクセルです。SSAA 4x を使うと内部の大きさは 15360×8640 になり、約 1億3270万ピクセルです。RGBA8 の色のバッファー1つで約 531 MB、32ビットの深度バッファー1つでも約 531 MB になります。resolve 用のターゲット、Bloom／SSAO／DoF の中間のテクスチャ、ラッパーのキャッシュ、ゲームのテクスチャを数えなくても、この2つだけで 1 GB を超えます。

さらに HSAA 4x を使うと、色と深度のターゲットに約4倍のマルチサンプルのデータを保存する必要があり、この2つのバッファーだけでも理論上 4.25 GB 近くになりえます。1フレームごとに約 1億3270万ピクセルのシェーディングと約 5億3080万の覆い／深度のサンプルの処理をし、その後 resolve して 4K に縮小し、いくつもの後処理のパスを行います。この負荷を主に制限するのはフィルレート・メモリの帯域・キャッシュ・ラッパーの実装で、モデルの三角形の数とはあまり関係がありません。

RTX 4090 と RTX 5090 はどう考えればよい？

RTX 4090 は 24 GB の GDDR6X、RTX 5090 は 32 GB の GDDR7 に増えています。NVIDIA の公式の仕様ではメモリの帯域はそれぞれ約 1008 GB/s と 1792 GB/s です。そのため SSAA／HSAA や複数の全画面のパスのように帯域とメモリの容量が重い負荷では、たいてい 5090 のほうが余裕があります。参照： NVIDIA の 5090 と 4090 の公式の仕様の比較。

ただし、5090 で PSOBB のフレームレートが帯域に比例して上がるわけではありません。Ephinea は32ビットの古いプログラムで、D3D8→D3D9→dgVoodoo／DXVK の状態の変換も通ります。ボトルネックは CPU の単一スレッド、同期、ドライバー、ラッパーの内部の上限、巨大なレンダーターゲットの確保にあることもあります。4090 は 4K + SSAA／HSAA 4x + SSAO High + 複数のシェーダーで負荷が100%になったり、30 FPS を下回ったり、リソースの確保に失敗して落ちたりすることがあります。5090 はたいていより余裕がありますが、どんな極端な組み合わせでも問題ないとは限りません。

実際の判断：古いハードウェアでなめらかなのは「本来の場面の負荷」をこなせるからで、最上位のグラフィックカードが苦しむのはプレイヤーが数百倍のピクセル、多くのサンプル、多くの全画面のパスを作り出しているからです。性能を判断するときは、「20年前のゲームだから」と言うだけや D3D11 と D3D12 を比べるだけでなく、組み合わせ全体を記録してください。

組み合わせ（X + SMAA）

SMAA は場面を描き終えた後の後処理の段階にあるので、MSAA・SSAA・HSAA の resolve や縮小の後に残った、コントラストの高い輪郭をさらに処理できます：

  • MSAA + SMAA — MSAA が本当の形状の覆いのサンプルを与え、SMAA が残った見分けられる輪郭を整えます。たいてい品質と負荷のバランスのよい組み合わせです。
  • SSAA + SMAA — SSAA が先に細かい細部とピクセルより細かいジャギーを抑え、SMAA が残った輪郭を処理します。品質は高いですが、SMAA では SSAA 自体の大きなピクセルの負荷は打ち消せません。
  • HSAA + SMAA — SSAA・MSAA・SMAA の3つを重ねる極端な選択肢で、普段使いの「妥協案」ではありません。

異方性フィルタリング（Anisotropic Filtering）

AF が解決するのは斜めから見たテクスチャのぼやけで、モデルの輪郭のジャギーではありません。床・壁・道が遠くへ伸びると、画面の1ピクセルがテクスチャの上で覆う範囲は正方形ではなく細長くなります。普通のバイリニア／トリリニアのフィルタリングはほぼ正方形の範囲でサンプリングするので、低すぎるミップマップを選んで遠くの細部を失いがちです。AF は長い方向にサンプルを増やし、斜めのテクスチャを鮮明に保ちます。

  • 2x / 4x:少ない負荷で床や壁の斜めの鮮明さを改善します。古い GPU や内蔵グラフィックに向きます。
  • 8x:たいてい目に見える効果のほとんどを得られ、汎用の設定に向きます。
  • 16x:斜めのテクスチャの鮮明さを最大にします。現代の単体のグラフィックカードでは追加の負荷はたいてい小さいですが、テクスチャのサンプリングと帯域の負荷は増えます。

AF でかえってちらつくことがあるのはなぜ？

AF は細かいテクスチャの細部を多く残します。本来のテクスチャや Mod のテクスチャに正しいミップマップがなかったり、強すぎるシャープや細い線があったりすると、鮮明になった遠景でちらつき・モアレ・ノイズが出ることがあります。これは AF の実装の誤りとは限りません。まず 16x を 8x／4x に下げるか、正しいミップマップのあるテクスチャに替えてください。SSAA でもこのジャギーをさらに抑えられます。

おすすめ：本来のテクスチャと現代の GPU なら AF 16x から始めます。カスタムの高解像度テクスチャを入れた後に遠くが大きくちらつくなら、8x／4x に下げてテクスチャパックのミップマップを確認してください。AF でキャラクターの輪郭のジャギーは消えないので、合った AA も必要です。

dgVoodoo Model（スワップチェーンの方式）

この設定は dgVoodoo の経路にだけ関係し、DXGI のスワップチェーンの Present の方式、つまり描き終えたバックバッファーを Windows のデスクトップの合成やディスプレイにどう渡すかを決めます。遅延・ウィンドウの互換性・Alt-Tab・画面の取り込みに影響しますが、場面そのもののサンプリングの画質は変わりません。

重要な制限：これらのモードは主に D3D11 の出力用です。dgVoodoo の公式の説明によると、D3D12 の出力は Flip Discard を使う必要があり、ランチャーにほかの選択肢が残っていても、D3D12 を従来の BitBlt のスワップチェーンに戻すことはできません。

  • Auto — dgVoodoo がバックエンドとウィンドウのモードに応じて自動で選びます。初期設定のおすすめです。
  • Discard — 従来の BitBlt 方式で、新しいフレームを表示するときに古いフレームを捨てます。Win 7 や古いドライバーで互換性が最もよいですが、Win10 以降の DWM の最適化は使えません。
  • Sequential — 従来の BitBlt 方式ですが、前のフレームを残します。あまり使われません。
  • Flip Discard — 現代の Flip 方式 + バッファーの中身を捨てる。不要なデスクトップへのコピーを減らし、現代の表示の最適化を使えます。実際の遅延は V-Sync・ウィンドウのモード・ドライバーのキュー・DWM のスケジュールにも左右されます。
  • Flip Sequential — Flip 方式ですが、古いフレームを残します。Flip Discard より少し負荷が高いです。

おすすめ：

  • D3D11 ではたいてい Auto で十分です。画面の取り込み・Alt-Tab・ウィンドウの合成がおかしいときだけ、ほかを1つずつ試してください
  • D3D11 で Flip に切り替えて録画ソフトが画面を取り込めなくなったら、 Discard
  • D3D12 で表示や取り込みに問題が出たら、Model を替えてもたいてい効果はありません。 D3D11 + Auto/Discard

画面効果が描画の流れのどこにあるか

下は概念的なデータの依存関係の図で、各設定が何を処理するかを理解するためのものです。Ephinea のソースコードの厳密な実行の順番ではありません。最も大事な違いは、MSAA／SSAA／HSAA は場面のサンプリングのしかたを変えるのに対し、SSAO・Bloom・DoF・Cel Shading・Tonemapping・SMAA はすでにできた画像や深度の情報を読み取ることです。

アンビエントオクルージョン（Ambient Occlusion）

SSAO（Screen-Space Ambient Occlusion）は画面の範囲内での接触の遮りの近似です。今のフレームの深度バッファー（実装によっては法線も）から近くの面の位置関係を復元し、壁の角・物のつなぎ目・キャラクターの足元など光が届きにくい場所をなだらかに暗くします。

動的な影でもグローバルイルミネーションでもありません。本当の影には、光源・遮る物・影を受ける面の関係が必要です。SSAO はカメラに今見えている限られた深度の情報しか知らないので、「物がより地面に接して立体的に見える」という見た目の手がかりしか与えられません。

  • Disabled — オフ。本来の見た目に最も近く、性能も最もよい。
  • Low — 低い解像度や性能の限られた機器に向きます。サンプリングのノイズ・縞・輪郭の変化が目立つことがあります。
  • Medium — 接触の感じと負荷のバランスがよく、普通のプレイヤーの出発点に向きます。
  • High — サンプリングと処理の品質を上げ、影はたいてい安定して細かくなりますが、負荷は出力の解像度とともに大きく増えます。

上級者が知っておきたい限界

  • 画面の端の漏れ：サンプリングの範囲が画面の外に出ると場面のデータがないので、遮りが急に薄くなったり消えたりすることがあります。
  • 遮りの情報が不完全：カメラの外や手前の物に完全に隠れた物は今の深度バッファーになく、正しい遮りに寄与できません。
  • 深度の段差でのにじみ：手前と奥の境目の大きな深度の差で、不自然な暗い縁や明るい縁ができることがあります。
  • 透明な物とパーティクル：透明な物・エフェクト・HUD は普通の物体のように深度を書き込まないことが多く、対象から外れたり、誤って覆われたりすることがあります。
  • AA との関係：SSAO／DoF はマルチサンプルの深度／色のバッファーを正しく読むか resolve する必要があります。Ephinea の 2022-09-06 の更新でこれらと MSAA／HSAA の組み合わせが個別に修正されたので、古いクライアントで問題が出たらまず完全に更新してください。

おすすめ：まず Medium キャラクターの足元・壁の角・画面の端を見て、にじみ・ノイズ・フレームの落ち込みがなければ High に上げます。本来の明るい雰囲気を保ちたいとき、敵の輪郭をはっきり見たいとき、シェーダーの落ちる不具合を調べているときは Disabled。

Extra（追加機能）

これは Ephinea が本来の上に追加した体験のためのスイッチで、画質とは関係ありません。緑＝オン、灰色＝オフ。

  • FAST STARTUP — 起動時の SEGA／Sonic Team／SOFTDEC などのロゴのアニメーションを飛ばし、すぐログイン画面に入ります。
  • CLEAN CAPTURE — ゲーム内蔵のスクリーンショットが場面のレンダーターゲットから「きれいな」画像を取るので、Lua Addons など後から重ねたものが写りません。録画の画質を上げるスイッチではなく、サードパーティの録画ソフトが取り込めるかはバックエンドとスワップチェーンによります。
  • MOTION BLUR — モーションブラー。動きの方向のサンプルを混ぜたり、隣のフレームを重ねたりして、シャッターが開いている間の動きの軌跡をまねます。低いフレームレートの動きを連続的に見せられますが、動いている間の細部と文字の読みやすさが下がります。PSOBB は 30 FPS 固定なので残像が特に目立ち、動きの鮮明さを重視する人や酔いやすい人はオフにしてください。
  • RARE DROP SFX — レアドロップの通知音。レアアイテムが落ちると追加の音が鳴り、周回中に見落としにくくなります。
  • BANK SHORTCUTS — 倉庫のショートカットキー。オンにすると倉庫の画面でキーボードを使ってすばやく出し入れやページ送りができ、効率が大きく上がります。
  • LARGE BANK WINDOW — 倉庫のウィンドウを大きくします。一度に多くのアイテムを表示し、ページ送りを減らせます。

スクリーンショットの互換性：Ephinea の開発者は、Clean Capture ではアドオンが写らず、D3D12 の内蔵のスクリーンショットでもアドオンは取り込めないとはっきり説明しています。アドオンの UI も一緒に写したいなら、まず D3D8／9 で Clean Capture をオフにするか、D3D11 で互換性のある Flip の表示方式を試してください。システムや OBS のウィンドウの取り込みを使ってもかまいません。

シェーダー（Shaders）

これは最終的な色・深度・輪郭の情報を使う画面の範囲内の後処理で、緑＝オン、灰色＝オフ。モデルやテクスチャの細部を増やすのではなく、すでに描いたピクセルを解釈し直します。いくつも重ねると負荷とゆがみも重なり、最終的な見た目は実行の順番にも左右されます。

  • BLOOM — ブルーム。よくある実装では、明るいピクセルを取り出し、解像度を下げた明るさの画像を何度もぼかしてから元の画像に足します。レンズや目の中で強い光が広がる感じをまねるもので、新しい光を作るわけではありません。強すぎると白い HUD・テクニックのエフェクト・明るいテクスチャが互いににじみ、白飛びや霧がかかったように見えます。
  • DEPTH OF FIELD — 被写界深度。深度バッファーからピクセルとピント面の距離（Circle of Confusion）を見積もり、ピントの外をぼかします。PSOBB の透明なエフェクト・キャラクター名・HUD は、実際の形状と同じ深度を持つとは限らないので、輪郭ににじみが出たり、手前が奥の色に染まったり、文字がぼやけたりすることがあります。
  • CEL SHADING — セルシェーディング。明るさ・深度・法線の輪郭の検出で輪郭を強め、連続した明暗の段階を減らして、セル画のアニメに近い見た目にします。画面の範囲内の様式化で、キャラクターの材質を作り直すものではありません。細かいテクスチャやコントラストの高い HUD も輪郭と見なされることがあります。
  • TONEMAPPING — トーンマッピング。非線形の曲線で内部の明るさを表示の範囲に割り当て直し、暗い部分の圧縮・明るい部分のなだらかさ・コントラスト・彩度を変えます。PSOBB は現代の HDR の描画ではないので、ここでは表示の色調と色の反応の調整と考えるべきで、何もないところから HDR のダイナミックレンジを作るわけではありません。

効果の重ね方と問題の調べ方

  • 1つずつ有効にする：まず安定したバックエンドと AA を選び、それからシェーダーを1つずつオンにします。そうして初めて、落ちる・ぼやける・フレームが落ちる・色がおかしいの原因がどれか判断できます。
  • Bloom + Tonemapping:トーンマッピングで明るい部分やコントラストが上がると、ブルームが取り出す明るい領域も変わります。組み合わせた結果は2つの効果の単純な足し算ではありません。
  • DoF / SSAO + MSAA:どちらも深度の resolve に依存します。クライアントを最新に保ち、輪郭ににじみが出たら、まず AO を下げて DoF をオフにし、それから AA を替えます。
  • 複数の全画面のパス：後処理はたいてい出力のピクセルごとに実行され、4K は 1080p の4倍のピクセルです。1つが軽いからといって、同時に使っても軽いとは限りません。
  • Vulkan / Wine:シェーダーのコンパイル、深度の形式、注入型のオーバーレイの組み合わせはより複雑です。落ちる不具合が出たら、まずシェーダーをすべてオフにし、バックエンドが安定しているのを確認してから戻します。

本来の見た目と見やすさ優先：4つともオフ。軽い現代化：まず Tonemapping だけをオンにし、好みでブルームを加えます。アニメ風：Cel Shading だけをオンにし、輪郭がきれいか確認します。スクリーンショットの雰囲気：DoF + Bloom を試してもよいですが、遠くの敵やドロップを見分ける必要があるときに使い続けるのはおすすめしません。

よくある質問

Q：切り替えたらゲームが黒い画面になった／落ちた。どうすればいい？
A：ランチャーを開き直し、 Direct3D 9 か Direct3D 11 (2.79.3) のような控えめな選択肢に戻せば大丈夫です。設定は描画にだけ影響し、キャラクターのデータが壊れることはありません。

Q：なぜバージョン番号が2つある（2.79.3／2.87.1）？
A：dgVoodoo／DXVK のバージョンごとに、直った不具合と新しく出た不具合が違うからです。旧版は戻るための予備として残し、新版は試すためのものです。新版で不具合に当たったら、ひとまず旧版に戻せます。

Q：設定を変えたのにフレームレートが変わらない？
A：PSOBB の本来のフレームレートの上限は 30 FPS で、変換レイヤーでもゲーム内部のフレームの固定は超えられません。バックエンドを替える主な目的は安定性と互換性で、高いフレームレートではありません。

Q：まだ落ちる。描画とは関係ない？
A： 落ちる問題について を参照し、DEP・互換性・UAC・ウイルス対策ソフトの除外などのシステムの設定を確認してください。

Q：アンチエイリアスを有効にしても効かない／違いがないのはなぜ？
A：高度な AA は Ephinea のクライアントがレンダーターゲットと後処理の段階で実装しているもので、dgVoodoo／DXVK が自動で与えるものではありません。高度な選択肢がすべて使えるのは D3D9 以上で、D3D8 は高度な AA の経路には向きません。MSAA は形状の輪郭だけを処理するので、テクスチャの内側はちらついたままです。それを改善したいなら SSAA を、軽くなめらかにしたいだけなら SMAA を試してください。

Q：D3D9on12 はすでに D3D12 を使っているのに、なぜ D3D12 を選ぶの？
A：D3D9on12 は D3D9 の命令を D3D12 に当てはめる Microsoft のシステムの互換レイヤーで、上には D3D9 のデバイスの仕組みが残っています。ランチャーの D3D12 は、dgVoodoo が D3D9 の再現・リソース管理・Flip の表示を引き受けます。同じなのは最終的なドライバーの API だけで、変換するものと互換性の動作はまったく違います。従来の Device Lost を避けるなら dgVoodoo の D3D11 を優先し、AMD で特定の D3D11 のテクスチャの異常があるときだけ D3D12 を考えてください。

Q：D3D12 は Microsoft 版の Vulkan と考えていい？
A：入門のたとえとしてなら構いません。どちらも命令・リソースの状態・ディスクリプター・パイプライン・同期を明示的に管理する現代の低水準の API です。ただし同じ API でも、互いのラッパーでもありません。D3D12 は Windows／Xbox のエコシステムに属し、Vulkan はクロスプラットフォームの規格です。PSOBB について正確に言えば、dgVoodoo は D3D9 を D3D12 に、DXVK は同じ種類の処理を Vulkan に変換しています。

Q：シェーダーをオンにしたら画面がぼやけた／色が変わった？
A：それは後処理そのものの性質で、不具合ではありません。よくある原因は BLOOM （ぼやけ）と TONEMAPPING （色が濃く鮮やかになる）です。1つずつオフにして、気に入らないものを特定してください。

Q：CLEAN CAPTURE と dgVoodoo Model = Discard にはどんな関係がある？
A：どちらも「録画／配信で画面を正しく取り込めるか」に関係します。まず CLEAN CAPTURE をオンにし、D3D11 でも OBS が取り込めないなら、Model を Flip 系から Discard に戻します。D3D12 は常に Flip Discard なので、Model を試すには D3D11 に替えてください。
